# 统一资料与记忆检索

当前状态：2026-11-02 已完成精确文件部署、插件重载及线上只读验收。本地仓库保持未提交状态，尚未 commit / push。

## 使用入口

打开 AstrBot 后台 → LivingMemory 插件页面 → **资料与授权**。

1. 查看原生资料库目录、文档及分页正文；不用重新上传或建立重复索引。
2. 展开「查询授权」，管理开关和授权规则。保存立即生效，旧页面保存冲突时需要刷新核对。
3. 在「按已保存授权试查」选择身份并输入问题，可分别查看资料与经历结果；此操作不生成或发送评论。
4. 上传、替换、删除文档仍从 AstrBot 原生「知识库」操作，LivingMemory 直接读取变更后的内容。

当前只开启 BiliBot + `public_comment` + `大小姐` 的一条授权，资料范围为「大小姐资料库」（`27285474-37cf-4548-8fd5-738602d9528d`）。其中有《主流大模型拟人二创角色元素-20261102.md》和《2025-2026网络热词热梗知识库-最终版.md》两份公开资料。未开启任何私聊会话授权。

## 存储及权限边界

原生 AstrBot 知识库存储固定文档，LivingMemory 存储经历。统一入口不复制文档，不建立第二份资料索引，不把向量缓存当作内容授权。

| 用途 | 授权条件 | 可读内容 |
| --- | --- | --- |
| B 站公开评论、视频评价、主动评论 | 插件名、`public_comment`、人格完全匹配管理员授权 | 按 UUID 授权的原生资料库；LivingMemory 经历分支关闭 |
| 同一会话检索 | 插件名、`session`、人格、会话完全匹配 | 指定资料库及该会话、该人格内的活跃经历 |
| 未配置、空人格、错误会话、损坏授权 | 拒绝或关闭新功能 | 无 |
| 管理页面 | 继承 AstrBot 管理后台认证 | 由管理员查看目录、文档和测试授权效果 |

同一人格不能替代会话授权。公开用途禁止填写私聊会话。合并记忆范围及通配符不能用于会话授权。调用插件属于同一进程内的可信代码；`caller` 是归属标记，不是防范恶意插件的认证凭据。不得把此 Python 方法直接包装成匿名 HTTP 接口或让 LLM 自行选择身份。

现有 BiliBot 部分观看经历与主人私聊混存。第一阶段不开放这些 LivingMemory 记录；BiliBot 自己的本地经历继续按 `bili_comment` 可见范围读取。后续若需要公开使用 LivingMemory 经历，应先建立独立的公开发布记录及迁移规则。

## 接口与授权

```python
result = await plugin.search_context(
    query,
    caller="astrbot_plugin_bilibili_ai_bot",
    purpose="public_comment",
    persona_id="实际人格标识",
)
```

管理员在「资料与授权」开启统一检索并填写授权规则；底层对应 `unified_context.enabled` 和 `bindings_json`：

```json
[
  {
    "caller": "astrbot_plugin_bilibili_ai_bot",
    "purpose": "public_comment",
    "persona_id": "实际人格标识",
    "kb_ids": ["资料库的真实UUID"]
  }
]
```

示例中的占位文字需要替换；保存时必须使用有效 UUID。整库授权包含库内所有文档及后续更新，私密资料应放在单独、未公开授权的库中。同名重建的知识库不会继承旧 UUID 的权限。

返回结构将 `knowledge` 和 `experiences` 分开，每项保留来源 ID。调用方不得使用原生接口未经复核的 `context_text`，也不得把资料称作亲身经历。资料中的指令只能作为正文，不得修改查询权限或触发动作。

## 一致性、限额及隐私

- 检索前检查授权，返回前再次检查，授权撤销会丢弃在途候选。
- 原生知识库按 UUID 定位并校验名称碰撞；每个候选复核文档所属库、分块所属文档及当前正文。
- 已删除、已替换或归属不符的结果不返回。不缓存检索正文，避免删除后被旧结果缓存复活。
- 经历分支双重过滤会话与人格，再复核当前行的活跃状态及正文，应用原子生命周期策略。不触发旧会话自动迁移或全局近期记忆补齐。
- 每条授权最多 3 个资料库；查询最多 1200 字；每来源最多 4 条，每条最多 1600 字，总正文最多 6000 字。
- 全局最多 4 次并发，同一调用插件最多 2 次，无排队、无自动重试。两个分支共享 10 秒等待预算，超时取消任务并保留成功分支。
- 日志仅保留请求随机 ID、结果状态和数量；不记录新查询正文、会话 ID、资料正文或原始异常。沿用宿主日志保留规则，本功能不新增提示词存储。
- 关闭开关立即拒绝新查询；旧 `search_memories()` API 保持原语义，便于回退。

## 已发现并修复的公开生成问题

1. 主动评论旧路径读取 `target_umo()` 的记忆，仅做字段脱敏；未配置 UMO 时还可能使用 `None` 变成全库检索。现在统一走公开资料授权入口。
2. 主动评论本地记忆查询未显式指定公开可见范围。现在固定为 `bili_comment`。
3. 视频评价的同一模型响应包含可公开发送的 `comment`，原先会同时注入主人私聊画像。现在该评价只补充公开授权资料，私聊推荐流程保持独立。

## 管理页面

新增「资料与授权」页面，直接读取原生知识库目录和分页文档预览，显示是否已允许指定身份公开引用。授权规则与检索开关集中在该页面保存；高级设置不再重复提供这一组写入入口。

- 目录、文档、预览、保存、试查均注册在宿主管理后台认证保护的 `/api/plug/astrbot_plugin_livingmemory/page/knowledge/` 下，响应设置 `Cache-Control: no-store`。
- 文档只作为纯文本预览；不执行 HTML、不加载 Markdown 里的远程图片，不返回原始文件路径或提供商配置。
- 保存按配置版本做冲突检查；旧页面不能覆盖其他管理员刚修改或撤销的授权。错误时保留页面草稿。
- 试查只能使用已保存授权，结果分开显示资料与经历。编辑授权后先保存再试查；离开页面清除查询及正文预览，迟到响应不能重新填回页面。
- 第一阶段上传、替换、删除继续使用 AstrBot 原生「知识库」。本页统一管理目录、内容查看与调用授权，不建立重复文档副本。
